# Конструктор образовательных программ

Веб-приложение для подготовки программ ДООП, ДПП ПК и ДПП ПП по утверждённым макетам. Проект хранит данные на сервере, поддерживает личные кабинеты, роли, комментарии проверяющего, рабочие программы дисциплин/разделов и выгрузку редактируемого `.docx`.

## Что входит в проект

- выбор типа программы: ДООП, ПК, ПП;
- личный кабинет автора со списком программ и статусами;
- роли `author`, `reviewer`, `admin`;
- переключение администратора между рабочими ролями автора и проверяющего;
- серверное хранение программ, РПД/РПР, комментариев и статусов;
- комментарии проверяющего к полям, строкам и числовым значениям;
- критические ошибки, блокирующие отправку/выгрузку;
- DOCX-выгрузка программ по структуре макета;
- библиотека РПД/РПР с возможностью взять утверждённый раздел за основу.

## Важное про GitHub

Это не статический сайт для GitHub Pages. Приложению нужны серверные API, база данных, авторизация и генерация DOCX. Поэтому корректный вариант для GitHub — хранить в репозитории полный исходный код, а запускать приложение на сервере или в контейнерной среде.

GitHub Pages можно использовать только для отдельной демонстрационной HTML-страницы без БД, авторизации и полноценной выгрузки. В этом репозитории сохранён именно рабочий серверный вариант.

## Текущая архитектура

| Слой | Сейчас | Для переноса на ваши серверы |
| --- | --- | --- |
| Интерфейс | React / Next / Vinext | Без изменения или адаптация под выбранный runtime |
| API | серверные маршруты `app/api/*` | тот же контракт API |
| База данных | Cloudflare D1 через Drizzle | PostgreSQL / Postgres Pro через новый адаптер |
| Авторизация | Sign in with ChatGPT | корпоративный SSO/OIDC |
| DOCX | серверная генерация через `docx` | серверная генерация в том же сервисе |

Подробности переноса: [`docs/server-architecture.md`](docs/server-architecture.md) и [`docs/self-hosting.md`](docs/self-hosting.md).

## Структура проекта

```text
app/                 страницы, рабочая область и API-маршруты
components/          UI-компоненты
```

## Быстрый старт для разработчика

Требуется Node.js `>=22.13.0` и pnpm.

```bash
pnpm install
pnpm run dev
```

Локальный режим текущей Sites-сборки использует платформенную имитацию авторизации и D1. Для промышленного запуска на ваших серверах нужно подключить PostgreSQL-адаптер и корпоративный OIDC, как описано в документации по self-hosting.

## Основные команды

```bash
pnpm run dev          # локальная разработка
pnpm run build        # сборка
pnpm run start        # локальный запуск собранного worker/runtime
pnpm run db:generate  # генерация миграций Drizzle после изменения схемы
pnpm run lint         # статическая проверка
```

## Переменные окружения

См. `.env.example`. В репозиторий нельзя добавлять реальные секреты, строки подключения к БД, client secret, токены и выгруженные пользовательские данные.

## База данных

Прикладная схема находится в `db/schema.ts`, SQL-миграции — в `drizzle/`.

Ключевые таблицы:

- `programs` — программы, статус, данные формы, комментарии проверяющего;
- `disciplines` — рабочие программы дисциплин/разделов;
- `user_profiles` — роли, отображаемое имя, email и активная роль администратора.

## Роли

- Автор создаёт и редактирует программы до отправки на проверку.
- Проверяющий комментирует поля/строки/цифры и отправляет программу на доработку или согласует.
- Администратор назначает роли и может работать в режиме автора или проверяющего.

## DOCX-выгрузка

Формирование документа находится в `lib/program-export.ts`. Требования к выгрузке:

- формат OOXML `.docx`, редактируемый;
- A4, книжная ориентация;
- поля и шрифты по макету;
- порядок разделов и нумерация по утверждённому образцу;
- литература собирается автоматически по ГОСТ Р 7.0.100-2018;
- файл именуется по шаблону `ДПП_ПП_[Наименование]_[Год].docx`.

## Подготовка к публикации в GitHub

Перед загрузкой репозитория:

1. Проверьте, что в проекте нет `.env`, дампов БД, персональных данных и временных токенов.
2. Не добавляйте `node_modules`, `dist`, `.wrangler`, `.sites-runtime`.
3. Загрузите исходники, `pnpm-lock.yaml`, `drizzle/`, `docs/` и `.env.example`.
4. Настройте секреты уже в среде запуска, а не в GitHub-репозитории.

## Что ещё нужно сделать для полного self-hosting

- реализовать PostgreSQL-адаптер вместо текущего D1-адаптера;
- реализовать OIDC-адаптер вместо текущей Sites-авторизации;
- добавить журнал действий администратора и проверяющего;
- утвердить схему резервного копирования БД;
- провести тестовую миграцию данных и сверить DOCX-выгрузку с макетами.
